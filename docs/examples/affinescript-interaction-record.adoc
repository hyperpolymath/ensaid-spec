= AffineScript Example: Interpretation, Authority, Execution and Evidence
:status: Illustrative; not an executed transaction
:toc:

== Situation

A human requests: "Refactor an AffineScript parser path to make resource consumption clearer, without changing the ownership discipline or quietly substituting another language."

The assistant proposes a refactor, but the human may mean either making resource movement visible in source or changing only explanatory material. The interpretations need not be treated as equivalent.

This example contains *no actual execution*, compiler output, proof, BoJ receipt, or Hypatia result. It shows the record states that would be required to report such work accurately.

== How the record changes with legitimate progress

. *Interpretation accepted:* record the human's clarification as a new, attributable decision. Do not delete the agent's initial interpretation.
. *Authorisation granted:* reference the actual authority, allowed file scope, expiry, and side effects. An interaction record cannot grant itself authority.
. *Action dispatched:* use an existing authorised tool or BoJ capability. Record invocation identity separately from acceptance and completion.
. *Execution completed:* attach an authentic executor receipt. An empty or model-authored receipt is not evidence.
. *Semantics checked:* record actual compiler/proof/test artefacts and their observed results, using the authoritative AffineScript capability and soundness status sources.
. *Continue:* cite the predecessor ID, what changed, remaining disagreement and outstanding obligations.

== Important translation distinction

AffineScript is designed to elaborate language-shaped faces into its own checked core and compile to supported targets. Therefore, a blanket prohibition on translation into host languages is wrong. The relevant restriction is against *unverified semantic substitution*. Section 09's four fidelity levels should accompany every claimed translation.

Do not claim `exact` for a heuristic rewrite merely because it compiles. A successful build establishes only the tested property of that build unless further semantic evidence exists.

== Boundary assertions

* PanLL/eNSAID presents and mediates interaction but does not replace the human's authority.
* BoJ coordinates or dispatches capabilities but does not certify AffineScript semantics.
* Hypatia may supply relevant governance findings; it is not the type checker.
* A history of records supports provenance and accountable continuation, not by itself diachronic identity.
